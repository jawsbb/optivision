# Gemini Vision Pipeline — Design

**Date:** 2026-05-22
**Status:** Approved

## Goal

Turn a Colab notebook for zero-shot object detection into a packaged, testable
GitHub repository with a CLI and a reusable Python API.

The notebook works but is not reusable: logic lives in cells, the Gemini client
is built from Colab `userdata`, and the same detection block is duplicated ten
times. The target package collapses that block into one `ObjectDetector` call.

## Scope

- **In scope:** the `gemini_vision` package, a `gemini-vision` CLI, three example
  scripts, mocked unit tests, project tooling, and documentation.
- **Out of scope:** real Gemini API calls in tests, image hosting, model
  fine-tuning, batch processing.

## Stack

- Python 3.11+, managed with `uv`
- `google-genai` — official Gemini SDK
- `supervision` — VLM result parsing and annotation (Git branch, see Risks)
- `pydantic` v2 + `pydantic-settings` — config and schemas
- `typer` — CLI
- `pytest` — tests
- `ruff` — lint and format
- `pillow` — image I/O

## Module Specifications

### `config.py`

`Settings` reads `.env` through `pydantic-settings`:

```python
class Settings(BaseSettings):
    google_api_key: SecretStr
    gemini_model: str = "gemini-3.5-flash"
    default_temperature: float = 0.0
    default_thinking_budget: int = 0  # 0 = thinking off (fast)

    model_config = SettingsConfigDict(env_file=".env", env_prefix="")
```

`get_settings()` is cached with `@lru_cache`.

### `schemas.py`

```python
class Detection(BaseModel):
    label: str
    confidence: float = Field(ge=0, le=1)
    box_2d: list[int] = Field(min_length=4, max_length=4)

class DetectionResult(BaseModel):
    detections: list[Detection]
    classes: list[str]
    model: str
    image_size: tuple[int, int]
    raw_response: str | None = None
```

`DetectionResult` carries no response-time field. The brief's prose mentions one,
but its code block omits it; the code block is authoritative.

### `prompts.py`

`DETECTION_PROMPT_TEMPLATE` is a module-level constant, migrated verbatim from the
notebook. `build_detection_prompt(classes: list[str]) -> str` injects the class
list and an example class into the template.

### `client.py`

`get_client()` returns a `genai.Client` built from `Settings`, cached with
`@lru_cache`. The client is never built from Colab `userdata` — that was the
notebook's main debt.

### `detector.py`

`ObjectDetector` is the pipeline core.

```python
class ObjectDetector:
    def __init__(
        self,
        model: str | None = None,
        temperature: float = 0.0,
        thinking_budget: int = 0,
    ): ...

    def detect(
        self,
        image: Image.Image | str | Path,
        classes: list[str],
        structured_output: bool = False,
    ) -> DetectionResult: ...

    def detect_and_annotate(
        self,
        image: Image.Image | str | Path,
        classes: list[str],
        with_labels: bool = True,
        structured_output: bool = False,
    ) -> tuple[DetectionResult, Image.Image]: ...
```

`image` accepts an `Image.Image`, a `str`, or a `Path`. When `structured_output`
is `True`, the call sets `response_mime_type="application/json"` and
`response_schema=list[Detection]` for dense scenes.

The detector builds `sv.Detections` internally with
`sv.Detections.from_vlm(vlm=sv.VLM.GOOGLE_GEMINI_3_5, ...)`. `detect_and_annotate`
passes that object to the annotator.

### `annotator.py`

`COLOR` (a `sv.ColorPalette`) is migrated verbatim. `annotate()` takes an
`sv.Detections` object, matching the notebook and the supervision API:

```python
def annotate(
    image: Image.Image,
    detections: sv.Detections,
    with_labels: bool = True,
    max_size: int | None = None,
) -> Image.Image: ...
```

The notebook's fixed `thumbnail((1000, 1000))` becomes the optional `max_size`
parameter. Default `None` means no resizing.

### `cli.py`

A `typer` app with one `detect` command:

```bash
gemini-vision detect image.jpg --classes "car,truck,bus" --output annotated.jpg
gemini-vision detect image.jpg --classes "person" --structured
gemini-vision detect image.jpg --classes "car" --no-labels --json-out detections.json
```

Options: `--classes` (comma-separated), `--output`/`-o`, `--json-out`,
`--structured`, `--no-labels`, `--model`.

### `examples/`

Three standalone scripts, roughly 15 lines each, with no duplicated detection
logic. Each imports from `gemini_vision` and calls `detect_and_annotate`.

| Script | Image | Classes | Mode |
|---|---|---|---|
| `01_single_class.py` | `pexels-eyup-sayar-290427017-18373303.jpg` | `["air balloon"]` | free-form |
| `02_multi_class.py` | `pexels-vanessa-loring-5966631.jpg` | 3 avocado classes | free-form |
| `03_structured_output.py` | `top-view-of-people-...-2026-03-24-21-54-59-utc.jpg` | `["person"]` | structured |

### `tests/`

No real API calls.

- `test_prompts.py` — `build_detection_prompt` injects the class list.
- `test_schemas.py` — Pydantic constraints (`confidence` in [0, 1], `box_2d`
  length 4).
- `test_detector.py` — mocks `client.models.generate_content`, verifies JSON
  parsing and the `sv.Detections.from_vlm` call.

### `scripts/download_examples.sh`

Nine `wget` commands from the notebook, downloading example images into `assets/`.

## Tooling

`pyproject.toml` declares project metadata, runtime dependencies, a `dev`
dependency group (`pytest`, `ruff`), the CLI entry point
(`gemini-vision = "gemini_vision.cli:app"`), and `ruff`/`pytest` configuration.
The build backend is `hatchling` with a `src` layout.

`supervision` is pinned to a Git branch through `[tool.uv.sources]`:

```toml
[tool.uv.sources]
supervision = { git = "https://github.com/roboflow/supervision.git", branch = "add-gemini-3.5-vlm-support" }
```

## Deviations from the Brief

1. **`black` dropped.** `ruff format` is a black-compatible formatter, so the two
   overlap. The project uses `ruff` alone for lint and format.
2. **Dev dependencies in `[dependency-groups]`**, the native `uv` form.
3. **`supervision` Git pin in `[tool.uv.sources]`**, the correct `uv`/PEP 621
   form, rather than inline in `dependencies`.
4. **`pillow` declared explicitly.** The code uses `PIL.Image`; a directly used
   dependency must be declared, not relied on transitively.
5. **`DetectionResult` has no response-time field**, following the brief's code
   block over its prose.

## Risks

- **`gemini-3.5-flash` model name** and **`sv.VLM.GOOGLE_GEMINI_3_5`** are taken
  at face value from the brief and notebook.
- **`supervision` Git branch `add-gemini-3.5-vlm-support`** must stay installable.
  The README will note: replace with the PyPI release once Gemini 3.5 support is
  merged.

## Quality Criteria

- Type hints everywhere, checked by `ruff`.
- Google-style docstrings on public classes and functions.
- No duplication: the notebook's ten detection blocks collapse to one
  `detect_and_annotate` call.
- No secrets in code or commits.
- The CLI works after `uv sync` with no code changes.
- Tests pass with no real API calls.
- A new developer can clone and run the project in five minutes.

## Execution Order

Each step ends with a commit.

1. Bootstrap: `pyproject.toml`, `.gitignore`, `.env.example`, `.python-version`,
   `LICENSE`, empty package structure.
2. `schemas.py`, `prompts.py`, `config.py` — modules with no API dependency.
3. Unit tests for prompts and schemas (test-first).
4. `client.py`, `detector.py`, `annotator.py` — the core.
5. `test_detector.py` with a mocked Gemini client.
6. `cli.py` with `typer`.
7. The three example scripts.
8. Move the notebook to `notebooks/original_exploration.ipynb`.
9. `scripts/download_examples.sh` and the full `README.md`.
10. Lint pass: `ruff check --fix`, `ruff format`, confirm `pytest` is green.
